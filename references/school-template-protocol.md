# MarxDoctorPaper 学校模板与交付检查协议

博士论文交付不仅是正文，还包括模板、目录、批注、页码等装订线外的完整工程。本协议规定交付前必须逐项确认的事项。

## 一、模板字段

1. 使用用户提供的学校模板（封面、扉页、独创性声明、授权书、致谢、作者简历）。
2. **个人信息占位字段不得虚构**：姓名、学号、导师、副导师、专业、日期等，用户未提供的一律保留空线或占位符，并在交付说明中逐项列出待填字段。
3. 模板自带的底纹、字段底纹（如封面浅紫色底纹）保留原样，不擅自清除。
4. 逐页检查模板页是否与正文页码系统衔接（摘要、目录通常用罗马页码，正文起算阿拉伯页码）。

## 二、目录

1. TOC 域存在不等于目录可见：Word 只读导出的 PDF 里能看到目录，不代表 DOCX 里保存了目录缓存。
2. 交付前必须用可写方式更新目录并保存缓存：

```bash
python scripts/emarx_finalize_docx.py paper.docx --update-toc
```

3. 验证：重新打开 DOCX 确认目录条目可见、可点击、页码正确；PDF 中目录页视觉抽查。
4. 目录应覆盖：中文摘要、Abstract、绪论、各章（含节）、结语、参考文献、致谢、成果/简历。

## 三、批注与修订

1. 交付稿必须批注清零：`emarx_finalize_docx.py` 删除 comments.xml、commentsExtended.xml、commentRangeStart/End、commentReference；
2. 修订标记必须全部接受：w:ins 保留内容、w:del 移除内容；
3. 验证：脚本输出批注部件/标记/修订标记均为 0。

## 四、脚注与参考文献格式

1. 页下注：圈码 ①②③，每页重新编号，脚注文字宋体 9pt（以学校规范为准）；
2. 脚注规范见 `footnote-engineering-protocol.md`：一注一证、首次完整著录+后续短引、文集书级著录；
3. 文末参考文献（若学校要求保留）：GB/T 7714，编号连续，与脚注对应关系可追溯，悬挂缩进；
4. 一句话一个脚注；正文无学位论文身份括注。

## 五、字数与页码

1. 字数按学校口径实测（正文/含脚注/总字符），交付报告写明口径和数字，不混报；
2. PDF 导出后抽查：封面、摘要、目录、正文脚注页、参考文献末页、致谢页，确认无截断、无断页错误；
3. Word 打开时若提示"是否更新域"，说明目录缓存或字段状态异常，回到第二节处理。

## 六、环境异常处理

- Word/WPS 文件占用导致构建静默失败：先关闭占用进程再重建，旧校验结果作废；
- 本机无 LibreOffice 时，PDF 用 Word/WPS 导出链生成，再用 PDF 渲染工具（如 Poppler）做视觉复核；
- 每轮重建后必须重新审计，不沿用旧版本的对账数字。

## 七、最终交付清单

- [ ] 模板字段：已填/待填清单；
- [ ] 目录：缓存已写回、条目可见、页码正确；
- [ ] 批注/修订：均为 0；
- [ ] 脚注：闭环对账通过，一注一证；
- [ ] 参考文献：编号连续，GB/T 7714；
- [ ] 字数：实测数字与口径；
- [ ] PDF：页数、抽查页列表；
- [ ] 查重与 AIGC 预检状态；
- [ ] 残余风险与待用户确认事项。
